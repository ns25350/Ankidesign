# 表示と操作の検証

検証対象は、現在の `templates/表面.txt`、`templates/裏面.txt`、`templates/CSS.txt` です。Ankiのフィールド・条件付き表示をサンプル内容で展開し、Chromium 151で表示しました。

## カードが内容に合わせて伸びること

長い答えは段落2つと箇条書きを含みます。下の表の高さはメインカードの実測値です。

| 画面幅 | 短い答えの高さ | 長い答えの高さ |
| --- | ---: | ---: |
| 320px | 190px | 約1524px |
| 390px | 190px | 約1249px |
| 480px | 190px | 約1035px |
| 768px | 210px | 1121px |
| 1024px | 210px | 1121px |

すべての幅で、答えがメインカードの内側に収まり、単語情報と例文がその下に並ぶことを確認しました。カード全体の横方向のはみ出しはありません。画面より長い答えは、通常の縦スクロールで読めます。

## 確認した操作・内容

- 表面を読み込む場合と、表面スクリプトを実行せずに裏面を読み込む場合。
- 引用符・バックスラッシュ・HTMLの改行・段落・箇条書き・長い連続文字列。
- 空の答え、空の改行タグだけの答え、空の例文・日本語訳。
- 初期表示の後に画像を読み込み、カードの高さが増えて下の枠が移動すること。
- 幅の広い表が表の中で横スクロールでき、画面全体を押し広げないこと。
- テーマ切替、表面から裏面への色の保持、不正な保存色からの復帰、保存領域が利用できない場合。
- 44px以上のボタン、名前の切り捨てがないこと、Tabでの移動、Enterでの選択、見えるフォーカス。
- 200%拡大、844×390pxの横向き、動きを減らす設定。
- OSのダークモードとAnkiのnightModeクラスでの4色の表示。

これらの確認中にJavaScriptエラーは発生していません。

## 文字色の確認

ライトモードの文字用アクセント4色と補助ラベル、ダークモードのアクセント4色と補助ラベルの計11組を計算しました。カードより暗めのライト背景 `#f0f0f2` と、ダークモードの選択ボタン面 `#2c2c2e` を基準に、すべて4.5:1以上（最小4.86:1）です。装飾用の明るいアクセントは文字用の色と分けています。

## Impeccableの静的検査

スキルの指示に従い、テンプレート3ファイルと展開済みHTMLを1回検査しました。途中の検査では、補助ラベルのコントラストに関する助言2件と、情報カードの外枠のpaddingに関する警告1件がありました。

補助ラベルはその後読みやすい色へ修正し、最終の配色計算とブラウザ検証を行いました。静的検査は背景グラデーションとダークモードを合成した推定を含むため、最終的なカード面の文字色は上記の配色計算で確認しています。検査そのものを再実行して「指摘ゼロ」としたわけではありません。

情報カードは外枠のpaddingではなく、各info-itemが16〜20pxの内側余白を持っています。中央の区切り線をカードの端まで通すための現在の構成です。レンダリングした画像でも文字が端に接していないことを確認し、意図して残しています。
