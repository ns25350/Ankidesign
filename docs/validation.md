# 表示と操作の検証

対象は現在の表面・裏面・CSSです。Ankiのフィールドと条件付き表示をサンプル内容で展開し、Chromium 151で表示しています。

## 表面から裏面へ、同じ枠が伸びること

表面を先に表示し、その問題の枠を保持したまま裏面の答えを追加しました。短い答えでも枠の高さが増え、問題の内容が保たれることを確認しています。以下はメイン枠の実測値です。

| 画面幅 | 問題だけ | 短い答えを表示 | 長い答えを表示 |
| --- | ---: | ---: | ---: |
| 320px | 約103px | 約216px | 約1501px |
| 390px | 約103px | 約216px | 約1195px |
| 480px | 約103px | 約216px | 約981px |
| 768px | 約127px | 約243px | 約1025px |
| 1024px | 約127px | 約243px | 約1025px |

短い答えは「りんご」、長い答えは段落2つと箇条書きのサンプルです。すべての幅で、答えが問題の枠の内側に収まり、単語情報と例文がその下へ移動することを確認しました。メイン枠のmin-heightは0px、max-heightはnoneです。

## そのほかの確認

- テンプレートから色切替のボタン・保存処理・CSSがなくなっていること。
- 表面のスクリプトを実行しなくても、裏面で問題と答えが表示されること。
- 段落、箇条書き、引用符、バックスラッシュ、HTMLによる改行。
- 空文字、空の改行タグ、ゼロ幅文字だけの答えでは、答えの線・ラベル・余白を出さないこと。
- 空の例文・日本語訳を表示しないこと。
- 長い連続文字列を折り返し、画面全体が横に広がらないこと。
- 後から画像を読み込むと同じ枠の高さがさらに増えること。
- 幅広の表を表の中で横スクロールできること。
- 200%拡大、844×390pxの横向き。
- 保存領域を使えない場合と、旧テーマのクラスが残っている場合でも、現在の配色で表示されること。
- OSのダークモード、AnkiのnightMode / night_modeクラス。

JavaScriptエラーは発生していません。

## デザインの検査

Impeccableのtypesetとpolishの方針に沿って、文字の強弱・整列・余白を整えました。ユーザーの指定は「シンプルだけど切れのあるデザイン」です。角丸は12px、メインの枠線は1px、問題の太さは700です。スマートフォンとデスクトップの裏面・ダーク表示を目視で確認し、表面からの伸縮はブラウザで測定しています。

テンプレート3ファイルと展開済みHTMLをImpeccableの検査ツールで1回検査し、指摘はありませんでした。

ライト／ダークの本文・補助文字・リンク・短い答え・選択した文字の計16組を、WCAGの相対輝度の式で計算しました。最小でも4.75:1で、いずれも通常の文字に必要な4.5:1以上です。代表値は以下のとおりです。

| 文字と背景 | コントラスト |
| --- | ---: |
| ライト：本文／白い枠 | 14.61:1 |
| ライト：補足の文字／青灰色の背景 | 4.75:1 |
| ライト：リンク／白い枠 | 6.42:1 |
| ライト：短い答え／白い枠 | 6.34:1 |
| ライト：選択した文字／淡い青の背景 | 12.24:1 |
| ダーク：本文／暗い枠 | 14.54:1 |
| ダーク：補足の文字／暗い枠 | 7.45:1 |
| ダーク：短い答え／暗い枠 | 9.56:1 |

配色の参照元と採用色は[デザイン方針](../DESIGN.md)に記載しています。Happy Huesの本家サイトは直接閲覧できなかったため、Happy Hues由来の公開パレットデータを確認しました。
